[2026-03-16] - WebSockets: fixes para entorno local Windows + ngrok
- Corregido el nombre del constructor de Echo en el blade: era LaravelEcho, es Echo (el CDN IIFE lo expone así).
- Separadas las variables de conexión para PHP vs browser:
    REVERB_HOST=localhost / REVERB_PORT=8080 / REVERB_SCHEME=http → PHP se comunica con Reverb directamente (evita error SSL de cURL en Windows).
    REVERB_CLIENT_HOST / REVERB_CLIENT_PORT → usados en el blade para que el browser se conecte via cloudflare tunnel.
    REVERB_SERVER_HOSTNAME → usado por Reverb para aceptar conexiones del hostname del tunnel.
- Agregada variable REVERB_SERVER_HOSTNAME en config/reverb.php (env('REVERB_SERVER_HOSTNAME', env('REVERB_HOST'))).
- Corregido enabledTransports en el blade: era ['wss'] (inválido), debe ser ['ws'] con forceTLS:true.
- Eliminado php artisan pail del script composer dev (requiere extensión pcntl, no disponible en Windows).
- Para desarrollo se necesitan 5 terminales: ngrok (puerto 8000), cloudflared (puerto 8080), composer dev, reverb:start, schedule:work.
- IMPORTANTE: la URL de cloudflare cambia cada vez que se reinicia cloudflared. Hay que actualizar REVERB_CLIENT_HOST y REVERB_SERVER_HOSTNAME en .env, correr config:clear y reiniciar reverb:start.

DESCRIPCIÓN:
Al pagar correctamente en MercadoPago y hacer click en "Volver a la tienda", aparece una
pantalla completamente negra con el texto "Not Found". La reserva queda en estado PENDING_PAYMENT.
El dinero sí se debita correctamente de la cuenta del pagador.

SÍNTOMAS OBSERVADOS:
- La pantalla negra viene de Cloudflare (el túnel), no de Laravel.
- Los logs de Laravel no registran NINGUNA entrada para esas requests → la request nunca llega a PHP.
- La URL de redirect de MP tiene el formato correcto:
  /reservation-success/{id}?payment_id=...&status=approved&collection_status=approved
- Reservation 94 fue corregida manualmente vía php artisan tinker llamando a la API de MP y marcando PAID.

1. Cloudflare bloquea la URL de back_url porque contiene parámetros que parecen sospechosos o porque
   el token de MP en la URL activa algún filtro de seguridad del túnel.
2. La URL de APP_URL en .env no coincide exactamente con la URL del túnel activo al momento del redirect
   (el túnel Cloudflare cambia cada vez que se reinicia cloudflared).
3. MP recuerda la back_url con la que se creó la preferencia (URL vieja del tunnel) y redirige a esa URL
   aunque el tunnel haya cambiado — Cloudflare resuelve el hostname del tunnel antiguo con "Not Found".
4. Hay un loop de HTTPS redirect o un manejo incorrecto del protocolo entre Cloudflare y Laravel que
   hace que la URL final sea inaccesible.
5. El usuario que intentó pagar tenía un error en su sesión (sesión rota/inconsistente) que pudo
   interferir con el flujo de pago, aunque esto no explicaría el "Not Found" antes de llegar a Laravel.
